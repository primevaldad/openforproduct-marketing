# Open for Product — Marketing Site

This is the **static marketing site** served at `openforproduct.com`.

## Stack

- **Framework:** Next.js 16 (App Router) with static export (`output: "export"`)
- **Styling:** Tailwind CSS v4
- **Animations:** framer-motion (used on the About page)
- **Icons:** lucide-react
- **Hosting:** Firebase Hosting (Classic) — site name `openforproduct-marketing`
- **No server-side code.** No API routes, no server actions, no database access.

## Project structure

- `app/` — Pages (homepage, about, how-it-works, blog, podcast, contact, support)
- `components/` — Shared components (Logo, MarketingPageShell, ProjectMatchForm)
- `firebase.json` — Hosting config with deploy target `marketing`
- `.firebaserc` — Maps target `marketing` → site `openforproduct-marketing`
- `out/` — Built static files (gitignored, generated by `next build`)

## Conventions

- **Branches:** Mostly work on `main` for simple page additions. Use `feature/<name>` for larger changes.
- **Build:** `npm run build:export` → generates static files in `out/`
- **Deploy:** `npm run deploy` (builds + deploys to Firebase Hosting)
- **Manual deploy:** `npx -y firebase-tools@latest deploy --only hosting:marketing --project open-for-product`
- **Commits:** Conventional commits (`feat:`, `fix:`, `chore:`)

## Linking rules

- Links to app routes (projects, feed, settings) → use `https://app.openforproduct.com/<path>`
- Links between marketing pages → use relative Next.js `Link` (`/about`, `/blog`, etc.)
- The ProjectMatchForm POSTs to `https://app.openforproduct.com/api/project-match`

## Important constraints

- **No dynamic routes.** Everything must be statically exportable (`next build` with `output: "export"`)
- **No `"use server"` directives.** No server actions. Any form submissions go to the app repo's API.
- **Design must match the app.** Use the same color palette (#b8512c accent, #f6f0e5 background, #292820 text, Lora serif, Inter sans-serif)
